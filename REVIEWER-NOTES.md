# Reviewer notes — iPage Quick GR and NG

Purpose: assist a librarian on the iPage individual product page by showing Goodreads statistics and direct Goodreads/NetGalley links above Notes. It does not submit orders or edit Notes. Version 1.0.4 augments the user's native selection-list Update click: it supplies the page's next-product URL as selReturnUrl to iPage's own form builder, preserving native validation and saving. It does not navigate before or replace that save request.

This is an unlisted/self-distributed extension. The fixed ID is ipage-quick-links@adele.local. The release's configured HTTPS update_url is for Firefox update checks only. All executable code is included as readable JavaScript. No build compilation, minification, remote code execution, AI service, or external JavaScript dependency is used.

Code map:
- content.js reads #pd-title, contributor links, and ISBN/EAN, and inserts a shadow-DOM panel above #add-to-sl-note-gb. A narrowly scoped click listener adjusts only the selection-list Update return URL and requests source-tab closure. Without a next-product link it retains the native return destination.
- background.js performs ISBN/title searches, verifies candidate book identity, and caches results locally. It maintains at most one regular background tab for Goodreads and one for NetGalley, reusing those tabs for any snapshot reads and leaving them open for staff inspection. An Update or Close click cancels pending work and closes only the source tabs owned by that iPage tab. Per-document session IDs keep late closure messages from affecting the next product. Explicit access blocks are reported. Goodreads deluxe-edition fallback strips explicit edition labels and requires the regular title and author to match; A final Goodreads fallback compares the title before the first colon and author after earlier searches fail. NetGalley matching is unchanged.
- A missing Goodreads want-to-read count triggers a cookie-free fetch (`credentials: omit`, no-store) of the already verified canonical book URL. If still unavailable, background.js checks extension.isAllowedIncognitoAccess before opening a new minimized private window. It copies only an exact public count from the same canonical book URL; other book data is retained from the original lookup. The helper tab is removed in finally and on cancellation; it never closes an entire window or reuses user-owned private windows. Explicit verification/access blocks are reported rather than worked around. A private window uses Firefox's shared private session; it is not a fresh cookie container. No new host or API permissions are requested.
- reader.js answers the extension's snapshot requests on the extension-opened Goodreads and NetGalley background tabs.
- core.js performs read-only DOM parsing, matching, and formatting.

Permissions are scoped to iPage, Goodreads, and NetGalley; local storage holds cached book results. Website content and search terms are declared in Firefox data collection permissions. No Notes text, passwords, or review prose is extracted for research.

Testing needs an authorized iPage account and an individual product opened from a selection list. No credentials are bundled. Goodreads/NetGalley behavior can depend on account and site access. Ask the submitter for an approved review environment if needed; no credentials should be invented or shared without account-owner authorization.

Validation for 1.0.4 included the supplied saved iPage HTML and native form builder: all submitted fields remain identical except selReturnUrl, which points to the next product; native validation failures still prevent submission; the last product retains its normal return destination. Node tests cover source-tab ownership, cancellation during tab creation and fetch, stale close messages, refresh, and owner-tab closure. Matching checks cover deluxe/regular title and author, wrong-author rejection, and unchanged rating formatting. Complete signed-in Firefox behavior, the server redirect after saving, and live Goodreads extraction remain unverified. The supplied account page is not included in source or the package.

1.0.5 validation: `node --test tests/*.test.cjs` covers the Dangerous Ground example, deluxe-before-subtitle search ordering, wrong-author rejection, unchanged rating formatting, anonymous fetch options, exact-book count checks, zero counts, private-access refusal, private-window cleanup on success/failure/timeout, and cancellation during fetch/window creation. Supplied iPage markup and native form code were also checked locally for unchanged Update payload/validation and visible missing-count guidance. Synthetic Goodreads DOM fixtures verify public-count parsing and friend-count exclusion. No live Goodreads session or real Firefox private-window UI was exercised; installation requires an authorized Firefox test. To exercise the fallback, enable Run in Private Windows in about:addons, remain signed out of Goodreads in private windows, and use Refresh on an iPage book whose signed-in Goodreads page omits the total count. Only anonymous fixtures and mocked browser APIs are included in the repository tests; no supplied account HTML is packaged.
